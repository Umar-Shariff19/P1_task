# Experiment records

This directory is for controlled future experiment plans and manifests. It does not hold regenerated official outputs from the cleanup phase. Every run must have a unique ID, source commit, protocol/configuration, environment, input split identifiers (without accessing prohibited data), output paths, artifact hashes, command, and result status. Record deviations and failures. Do not overwrite existing reports/checkpoints or claim new replication without running and documenting a valid experiment.

The experimental registry is `experiment_registry.md`. Proposed but unapproved experiments remain proposals, not results.
