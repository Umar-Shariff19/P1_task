# Experiment result status contract

The evaluator accepts well-formed single-class **evaluation** labels but does not invent ranking scores. It returns `result_status="INCOMPLETE_METRICS"`, `roc_auc=null` and `pr_auc=null`, with both metric statuses `UNDEFINED` and reason `single_class_labels`. Threshold-dependent metrics that are defined are retained. FPR/FNR and FP-per-1000 are null when their respective class denominator is absent, with explicit statuses and reasons.

Two-class valid evaluations return `result_status="COMPLETE"` with numeric ranking metrics. Invalid labels, probabilities, shape, or threshold raise a controlled `ValueError`; callers must treat that as a failed run, not a successful record. A single-class validation set cannot support the existing threshold-selection procedure and is rejected before test evaluation.

Experiment runners merge the evaluator fields into the ordinary result row. The Stage 4 raw CSV therefore retains the experiment row; null values are blank in CSV and accompanied by status/reason columns. JSON serialization uses `null` (and passes `allow_nan=False`). The Stage 4 aggregate and ablation reports retain undefined means as null/blank and include defined/undefined ROC-AUC counts; they do not substitute zero.

Stage 4 per-experiment execution delegates to `run_within_domain_experiment()` and `run_cross_domain_experiment()` through the report-schema adapters in `scripts/04_benchmark_models.py`. The runner propagates validation/fitting/evaluation exceptions; a result row is appended only after a successful return. Confusion-matrix files are deferred until all model evaluations complete. Synthetic coverage now includes the staged report-writing and publication boundary; see the publication behavior and limits below.

The Stage 4 benchmark prepares its six CSV reports, an evidence-status JSON sidecar, and confusion-matrix directory in a unique staging directory, reads the staged files back for structural/status validation, and publishes only that explicit output set. If supplied, a manifest is checked against the canonical schema; absence is recorded as `NOT_PROVIDED`. The sidecar always records authorization and filesystem identity as `NOT_ESTABLISHED`, integrity as `NOT_CHECKED`, and provenance/scientific validity/evidence as `UNVERIFIED`. Schema validity is not promoted into those statuses. Existing targeted outputs are first moved into a same-filesystem backup under the output parent; ordinary publication exceptions trigger removal of newly installed outputs and restoration of the backup. Unrelated files such as plots are preserved. This is rollback-based publication, not an atomic multi-file transaction: readers may see a brief transition, and process/host failure or non-cooperating concurrent writers can interrupt it. If rollback itself fails, the operation raises `ROLLBACK_INCOMPLETE` and retains the backup path for recovery. Ablation CSV generation and plot generation are separate commands and are not included in this Stage 4 benchmark publication set.

The isolated synthetic Stage 4 publisher accepts only destinations beneath the configured OS temporary directory and rejects repository destinations. It inspects an existing final component without following it and rejects symlinks and Windows reparse points when the required metadata is available; inspection errors fail closed. This pathname restriction is defense in depth for synthetic outputs, not production authorization, authenticated filesystem identity, or a race-free boundary against concurrent replacement. The public Stage 4 publisher continues to refuse before filesystem mutation while real-data authorization is unavailable.

The legacy ablation analyzer accepts its report directory as an argument for isolated tests. Every generated ablation row is labeled `evidence_status=UNVERIFIED`, because the source CSVs are not bound to authenticated provenance. Empty/missing profile groups retain null metrics and zero observed counts; they are not filled with baseline or zero-valued observations.

The two Stage 4 benchmark entrypoints (`scripts/04_benchmark_models.py` and `scripts/04_run_benchmarks.py`) now fail closed before path construction, data discovery, or output creation because the trusted real-data authorization provider is unavailable. The Stage 4 report publisher remains callable for isolated synthetic rows; its reports must not be treated as authorized research results. Other direct training/evaluation scripts remain outside this guard and must not be run under current restrictions.

`COMPLETE` means the requested evaluation metrics are defined and calculated; it is not a claim of authorization, scientific validity, or reproducibility. `INCOMPLETE_METRICS` means an evaluation row exists but at least its class-ranking metrics are undefined. No historical report is rewritten by this policy.

The current Stage 4 file-backed preflight independently requires both labels in every train, validation, and test split. The evaluator's single-class incomplete-result behavior does not relax that experiment-eligibility rule; tests of undefined test metrics exercise the evaluator/report contract directly with synthetic rows.
